Research & Experiments

How Research Works Today

The high-level research entry point is runBacktestExperiment(). It validates the experiment, loads the requested dataset once, generates valid parameter combinations, creates a fresh strategy for each run, executes every run against the same in-memory data, and returns one structured experiment result.

experiment config
      |
      v
plan + validate combinations
      |
      v
load D1 dataset once
      |
      +--> run 1
      +--> run 2
      +--> run 3
      +--> ...
      |
      v
schema-v5 experiment JSON

For ORB, the current human-facing entry point is src/experiments/orb-sweep.js. Run it with npm run research:orb.

Experiment Config Sections

The current experiment code is split into five important areas. The first four are generic; only strategy parameters differ by strategy.

SectionPurpose
backtestConfigInstrument, date range, strategy timeframe and execution timeframe.
accountConfigStarting balance, account currency, leverage, sizing and risk limits.
executionPolicySame-candle rule, slippage, commission and order handling assumptions.
policyResearch warning/maximum run limits.
baseStrategyConfig + parameterGridValues defined by the chosen strategy's own definition.

Account Config Options

initialCapital          positive number
currency                3-letter code, e.g. USD / GBP
quoteToAccountRate      fixed positive conversion rate when needed
leverage                positive number, e.g. 30 = 30:1
positionMode            HEDGING | NETTING
riskTimeZone            IANA timezone, default UTC
marginCallLevelPercent  positive number or null

defaultSizing.type      UNITS | CASH | PERCENT_EQUITY | RISK_PERCENT
defaultSizing.value     positive number

risk.maxOpenTrades
risk.maxTradesPerSide
risk.maxPositionUnits
risk.maxGrossExposure
risk.maxMarginUsagePercent
risk.maxDrawdownPercent
risk.maxDailyLossPercent
risk.breachAction       HALT_NEW_ENTRIES | CLOSE_ALL_AND_HALT

RISK_PERCENT is normally the most intuitive strategy-research sizing mode. A value of 1 means the engine sizes the position so that the configured stop represents about 1% of current equity. It requires a stop.

PERCENT_EQUITY is different: it sizes the notional position using a percentage of equity; it is not risk at the stop.

Execution Policy Options

sameCandleConflict      STOP_FIRST | TARGET_FIRST
slippagePips            non-negative number
commission.type         NONE | PIPS_PER_SIDE | FIXED_PER_ORDER | PERCENT_NOTIONAL
commission.value        non-negative number
closeOpenTradesAtEnd    true | false
rejectOnInsufficientMargin true | false
defaultTimeInForce      GTC | DAY | IOC | FOK

STOP_FIRST is the conservative default when one OHLC execution candle touches both stop and target and the true intrabar order is unknowable.

Research Policy

warningRunCount  default 250
maximumRunCount  default 5000
overrideLimits   developer override when intentionally exceeding the maximum

The Cartesian combination count is calculated before the experiment runs. Duplicate values in a sweep dimension are rejected.

Strategy-Specific Parameters

The main config does not need to know every possible strategy parameter. The selected strategy definition owns that information.

ORB currently exposes:

startHour
startMinute
durationMinutes
timeZone
stopLossPips
takeProfitPips

A different strategy can expose completely different fields. Its definition supplies type, defaults, min/max/options and any cross-parameter validation. This is also how a future UI can build strategy-specific forms dynamically.

Example ORB Sweep

baseStrategyConfig: {
    startHour: 8,
    startMinute: 15,
    durationMinutes: 60,
    timeZone: "America/New_York",
    stopLossPips: 10,
    takeProfitPips: 20,
},

parameterGrid: {
    durationMinutes: [30, 60, 90],
    stopLossPips: [8, 10, 12],
    takeProfitPips: [15, 20, 25],
}

This requests 27 backtests: 3 × 3 × 3.

What Comes Back

Each completed run records its exact strategy config, summary, yearly/monthly breakdown, rejection reason counts, dataset metadata and elapsed time. Optional trade detail includes holding time plus causal/conservative MFE and MAE.

Important summary fields include total trades, win rate, pips P&L, account P&L, return %, profit factor, expectancy and drawdown.

Why the Next Milestone Exists

The current engine is capable, but the user must know where these settings live. The next milestone will turn this into one obvious research.config.js plus npm run research. The browser UI will later be a visual editor for exactly the same model rather than a separate architecture.
