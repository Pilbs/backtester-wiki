Forex Backtester

Roadmap

Milestone Reached: Deterministic Engine

The first platform milestone is complete: historical data, generic strategy execution, bid/ask-aware fills, timezone-aware sessions, separate strategy/execution timeframes, trade intents, summaries and a real ORB regression case are all in place.

Next: Strategy Configuration

The next change should stay small. Move strategy parameter values into a plain configuration object without adding sweeps yet.

{
  strategy: "ORB",
  parameters: {
    startHour: 8,
    startMinute: 15,
    durationMinutes: 60,
    stopLossPips: 10,
    takeProfitPips: 20
  }
}

This separates strategy implementation from run-specific parameter values.

Then: Parameter Sweeps

Once configuration is structured, the research layer can generate combinations and call the existing backtest service repeatedly.

SL:       5, 10, 15, 20
TP:       10, 20, 30, 40
Duration: 30, 45, 60, 75

-> generate combinations
-> run deterministic backtests
-> rank and compare results

Experiments and Persistence

After basic sweeps, results should become first-class experiment data: run configuration, summary metrics and trade records. This will make comparisons repeatable and provide a clean interface for future automation.

AI Research Agent

The AI should control deterministic quantitative tools rather than calculate PnL itself. Future tools may include:

get_data_catalog()
run_backtest()
run_parameter_sweep()
compare_runs()
get_backtest_trades()

The loop becomes hypothesis -> backtest -> inspect -> refine -> robustness checks.

Pine Comes Later

Pine parsing is intentionally not the next problem. The eventual direction remains:

Pine Script
   |
   v
parser / compiler
   |
   v
internal strategy representation
   |
   v
existing backtest + research platform

Building the research platform first means Pine has a stable target to compile into later.
