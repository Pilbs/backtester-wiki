Forex Backtester

Market Data

Storage Model

Historical candles are stored in Cloudflare D1. The current EUR/USD database contains native OANDA M1 and M5 candles. The design is to shard by instrument rather than by timeframe, so one instrument database can contain multiple granularities.

EUR_USD database
  candles: M1, M5, future native timeframes

GBP_USD database
  candles: M1, M5, ...

The instrument and granularity columns remain part of the candle key even though each database is conceptually an instrument shard.

Candle Shape

OANDA candles are normalised into a common structure containing time, volume and BID / ASK / MID OHLC values.

{
  time,
  volume,
  bid: { open, high, low, close },
  ask: { open, high, low, close },
  mid: { open, high, low, close }
}

Strategy calculations use MID. Trade execution uses BID / ASK so spread is represented naturally.

Database Selection

The D1 client resolves the database from the instrument using environment variables such as:

CLOUDFLARE_D1_EUR_USD_DATABASE_ID
CLOUDFLARE_D1_GBP_USD_DATABASE_ID

This keeps database selection generic as more instruments are added.

Historical Import

The importer is generic over instrument, granularity and date range. Import progress is stored in the same D1 database so a historical load can resume after interruption.

npm run import-history -- EUR_USD M5 2021-01-03 2026-09-01

The canonical schema contains two tables: candles and import_progress.

Candle Reader

src/data/candle-reader.js returns chronological candles for a requested instrument, timeframe and date window. It uses keyset paging so callers do not need to care how many D1 query pages are required.
