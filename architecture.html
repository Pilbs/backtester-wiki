Forex Backtester

Architecture

Current Folder Model

src/
  backtest/      runner, service, context, summaries
  data/          OANDA, D1, import and candle access
  market/        instrument and timeframe metadata
  strategies/    generic contracts + strategy folders
    orb/          ORB implementation
  time/          timezone and session utilities
  tests/         focused regression tests
  import-history.js

The project was deliberately cleaned up after the initial build phase so development scaffolding does not become part of the long-term architecture.

Important Boundaries

  • Data layer: knows how to retrieve market history.
  • Market layer: describes instrument/timeframe facts needed by the engine.
  • Strategy layer: contains decision logic and state.
  • Execution layer: converts executable intents into simulated fills and outcomes.
  • Time layer: provides reusable timezone/session behaviour.

If a capability is useful to many strategies, build it generically. If it describes how one strategy behaves, keep it inside that strategy.

Design Direction

The service boundary around runBacktestJob() is intentional. It is the natural place for future APIs, parameter sweeps and AI tools to invoke deterministic backtests without needing to understand the runner internals.
